# OA v1 域边界：文件库、半天请假、Web 打卡、站内通知

**Status**: accepted

OA v1 交付公告、考勤、请假、报销、日程、会议室、文档七个域，bpm 作为独立引擎同时服务 OA 与 CRM。各域的边界按「去掉一个子系统、保留核心工作流」确定：

- **文档 = 文件库**：租户级目录树 + 目录 ACL（全员/部门子树/角色/用户），文件存 `infra_file`；不做 Wiki、在线 Office 预览、协同编辑、版本历史。共享资料的核心是「谁能看/谁能传」，不是内容协作。
- **请假 = 半天粒度 + 简单额度**：按工作日槽位计算，支持上午/下午，不支持小时；额度按自然年、按类型，支持手工调整；跨年请假拒绝，需拆单；不做自动累计、结转、按司龄计算。
- **考勤 = Web 打卡 + 日期级结果**：一人一天一个班次、不跨天，上下班各一次打卡，结果由打卡 + 已批准请假 + 工作日历派生；管理员校正用 override 字段，不覆盖原始打卡；不做 GPS/考勤机、加班、复杂弹性规则、员工补卡申请。半天请假只记录 `leave_days=0.5`，不改变日期级状态。
- **报销 = 审批 + 记录**：表头金额由明细行求和，审批通过即终态；不做付款/打款、预算、发票验真。付款属于 pay 域。
- **通知 = 站内信**：bpm 待办/结果、公告、会议提醒；同一事务写入、前端轮询未读数；不做 WebSocket、邮件、短信、企微/钉钉。
- **日程/会议室**：私有/部门子树/全员可见；会议室预约做时间冲突校验并自动生成日程；不做参会人邀请/回执、重复日程、外部日历同步、预约审批。

原因：单人全职、串行交付，完整 OA 若把 Wiki、设备考勤、付款、外部通知全部纳入，会同时引入四个独立子系统，首个里程碑无法收口。上述边界保留了每个域的核心闭环：公告能发能读、请假能批能扣额度、报销能批能对账、考勤能打能汇总、会议室能约不冲突、文档能控权限、通知能触达。代价：这些能力后续需要单独立项（Wiki、考勤设备、付款、外部通知）；半天请假的考勤精度有限，当前接受。
